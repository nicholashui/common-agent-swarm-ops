我再详细讲吓 Knowledge Router 嘅核心组件同架构。
Query Analyzer 加 Intent Classifier 系第一个组件。
佢分析请求代理嘅查询，
理解边个喺问、问乜嘢、点解要问。
加入 reflection 机制做自我校正。
如果初始分类唔确定会重新评估。
Planner 系第二个组件，
处理高复杂度或管道式查询。
对于需要多跳推理嘅复杂问题，
Planner 会分解成多个子步骤。
每个步骤嘅结果会影响下一步嘅检索策略。
Hybrid Retrieval Engine 系核心心脏。
有四个层次嘅检索策略。
第一层系 Metadata Hard Filters，
用确定性嘅元数据筛选快速消除无关文件。
呢个步骤可以即时消除 70 到 80% 嘅无关内容。
第二层系 Cluster 或 Centroid Semantic Retriever，
受 RopMura 启发用语义质心做检索。
唔需要预训练就可以 bootstrap 启动。
第三层系 Graph Explorer，
受 AgentRouter 启发用异构图神经网络或轻量遍历。
利用知识图谱中概念之间嘅关系做更智能嘅路由。
例如「角色一致性技术改善 Seedance 中嘅多镜头叙事」
呢种关系可以引导到更相关嘅知识。
第四层系 LLM Ranker 加 Reflection，
受 Self-RAG 启发做最终排序。
加入反思 token 评估检索结果嘅质量。
如果结果唔够好会触发重新检索。
Context Assembler 系第四个组件。
将原始 chunks 或综合知识包或结构化知识组装起嚟。
根据请求代理嘅需要选择最合适嘅格式。
Explainer 系第五个组件提供完整推理追踪。
100% 嘅决策都产出人类可读加结构化嘅追踪。
你可以准确知道点解呢啲文件被选中，
经过边啲检索策略同排序步骤。
Multi-Level Critic 系第六个组件系自我改善核心。
评估三个层面：检索质量、路由决策质量同下游效用。
检索质量评估返回嘅文件系咪真系相关。
路由决策评估整体策略系咪正确。
下游效用评估请求代理用咗知识后表现有冇改善。
呢啲评估反馈回嚟持续改善路由准确度。
知识库方面有超过五千个 md 文件。
每个文件都有丰富嘅 YAML Frontmatter，
包括 agent_relevance、tags、category、quality_score 等。
Vector Store 存储嵌入加元数据筛选。
Knowledge Graph 有节点包括技术、工具、失败模式、论文、代理，
关系包括 improves、requires、common_failure、used_with。
可选有预计算嘅 Centroids 按领域或代理集群分组。
成功标准好严格：
检索精度要大于等于 88% 通过 critic 或人类评估。

延迟标准查询小于 4 秒 p95，复杂查询小于 8 秒。
可解释性 100% 决策有追踪。
持续改善路由准确度随时间通过 critic 反馈提升。
成本效率避免过度检索支持成本感知路由。
